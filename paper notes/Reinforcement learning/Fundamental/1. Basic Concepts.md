## 1.1 Grid world

![[RL-Fig1-2.png|300]]

- An agent (robot) moves between adjacent cells. White cells are accessible, orange cells are **forbidden**, and the cyan cell is the **target**.
- **Goal:** find a good **policy** that reaches the target from *any* start cell, without entering forbidden cells, taking detours, or hitting the boundary.
- If the map were known, this would just be path planning. RL is needed because the agent does **not** know the environment and must learn by **trial and error**.

---

## 1.2 State and action

![[RL-Fig1-3.png|450]]

- **State** $s$: the agent's status relative to the environment (here, its location). State space $\mathcal{S}=\{s_1,\dots,s_9\}$.
- **Action** $a$: $a_1$ up, $a_2$ right, $a_3$ down, $a_4$ left, $a_5$ stay. Action space $\mathcal{A}(s)$.
- The action space **can depend on the state**. For example, one could set $\mathcal{A}(s_1)=\{a_2,a_3,a_5\}$ to rule out moving into the boundary. The book uses the general case $\mathcal{A}(s_i)=\{a_1,\dots,a_5\}$ for all $i$.

---

## 1.3 State transition

- Taking an action moves the agent: $s_1\xrightarrow{a_2}s_2$.
- **Hitting the boundary** bounces the agent back: $s_1\xrightarrow{a_1}s_1$.
- **Entering a forbidden cell**: the book assumes forbidden cells are *accessible but punished* ($s_5\xrightarrow{a_2}s_6$), which is the more general case. The alternative is to treat them as walls.
- In simulation we may define the transitions however we like; in the real world they are set by physics.

**Representations**
- A **table** (state × action → next state) only works for deterministic transitions.
- In general, use the **conditional probability** $p(s'\mid s,a)$. Example: $p(s_2\mid s_1,a_2)=1$, all others $0$. With wind gusts the transition could be stochastic, e.g. $p(s_5\mid s_1,a_2)>0$.

> [!tip] Probability theory (conditional probability and expectation) is a prerequisite for the whole book. See Appendix A.

## 1.4 Policy

![[RL-Fig1-4.png|500]]

- A **policy** tells the agent which action to take in every state. Drawn as arrows, it generates a trajectory from any initial state (b).
- Mathematically it is a conditional distribution $\pi(a\mid s)$, defined for every state.
  - **Deterministic**: $\pi(a_2\mid s_1)=1$, all other actions $0$.
  - **Stochastic** (below): $\pi(a_2\mid s_1)=\pi(a_3\mid s_1)=0.5$.

![[RL-Fig1-5.png|220]]

- **Tabular representation**: row = state, column = action, entry = $\pi(a\mid s)$. It can store both deterministic and stochastic policies. Ch8 replaces the table with a **parameterized function**.

## 1.5 Reward

- After taking action $a$ in state $s$, the agent receives a scalar **reward** $r(s,a)$ from the environment. Positive values encourage the action; negative values discourage it.
- **Grid-world design:** $r_{\text{boundary}}=r_{\text{forbidden}}=-1$, $r_{\text{target}}=+1$, $r_{\text{other}}=0$.
- **The target is not terminal.** At $s_9$: taking $a_5$ gives $+1$ again; taking $a_2$ hits the boundary and gives $-1$.
- Reward is a **human–machine interface**: we specify *what* we want, not *how* to do it. Designing rewards is non-trivial for complex tasks, but usually still easier than solving the task by other means.
- General form: $p(r\mid s,a)$. Rewards can be stochastic (studying hard → better grades, but how much better is uncertain).

> [!important] Greedy on immediate reward ≠ good policy
> Picking the action with the largest **immediate** reward does not give a good policy. We must look at the **total reward in the long run** (the return), because an action with a negative immediate reward can lead to large future rewards.

## 1.6 Trajectories, returns, and episodes

![[RL-Fig1-6.png|500]]

- **Trajectory**: a state–action–reward chain.
- **Return** (total / cumulative reward): the sum of the rewards along a trajectory.
  - Policy 1: $s_1\to s_2\to s_5\to s_8\to s_9$, return $=0+0+0+1=1$.
  - Policy 2: $s_1\to s_4\to s_7\to s_8\to s_9$, return $=0-1+0+1=0$.
  - ⇒ Policy 1 is better, which matches the intuition that it avoids the forbidden cell. **Returns can evaluate policies.**
- Return = **immediate reward** + **future rewards**. Decisions should be based on the return, to avoid being short-sighted.

### Discounted return
If the agent stays at $s_9$ forever, the plain return $0+0+0+1+1+\cdots$ **diverges**. Introduce a **discount rate** $\gamma\in(0,1)$:
$$
\text{discounted return}=\sum_{k=0}^{\infty}\gamma^k r_{k+1}
\;\Rightarrow\;
0+\gamma\cdot0+\gamma^2\cdot0+\gamma^3(1+\gamma+\gamma^2+\cdots)=\gamma^3\frac{1}{1-\gamma}
$$
Why discounting helps:
1. It allows **infinitely long** trajectories (no stopping criterion needed).
2. It sets the emphasis on near vs. far future. Small $\gamma$ gives a **short-sighted** policy. $\gamma\to1$ gives a **far-sighted** policy that is willing to take short-term negative rewards (see Sec. 3.5).

### Episodes
- **Episode (trial)**: a trajectory that stops at a **terminal state**, usually finite. Tasks with episodes are **episodic tasks**; tasks without terminal states are **continuing tasks**.
- With a stochastic policy or environment, starting from the same state gives different episodes.
- **Converting episodic to continuing** (so both can be treated the same way mathematically):
  - **Absorbing state**: once reached, the agent never leaves, e.g. $\mathcal{A}(s_9)=\{a_5\}$ or $p(s_9\mid s_9,a_i)=1$ for all $i$.
  - **Normal state**: same action space as the other states, so the agent may leave and come back. Since it earns $+1$ every time it is at $s_9$, it will *learn* to stay. **← used in this book** (needs $\gamma<1$ to avoid divergence).

## 1.7 Markov decision process (MDP)

An MDP is a general framework for describing stochastic dynamical systems.

| Ingredient | Content |
|---|---|
| **Sets** | state space $\mathcal{S}$; action space $\mathcal{A}(s)$; reward set $\mathcal{R}(s,a)$ |
| **Model (dynamics)** | $p(s'\mid s,a)$ with $\sum_{s'}p(s'\mid s,a)=1$; $p(r\mid s,a)$ with $\sum_r p(r\mid s,a)=1$ |
| **Policy** | $\pi(a\mid s)$ with $\sum_{a}\pi(a\mid s)=1$ |
| **Markov property** | memoryless (see below) |

$$
p(s_{t+1}\mid s_t,a_t,s_{t-1},a_{t-1},\dots,s_0,a_0)=p(s_{t+1}\mid s_t,a_t),\qquad
p(r_{t+1}\mid s_t,a_t,\dots,s_0,a_0)=p(r_{t+1}\mid s_t,a_t)
$$
The next state and reward depend only on the **current** state and action. This is what makes the Bellman equation (Ch2) possible.

- **Stationary vs. non-stationary model**: whether the model changes over time (e.g., forbidden cells that appear and disappear). The book only considers **stationary**, **finite** MDPs.

### MDP vs. Markov process

![[RL-Fig1-7.png|450]]

Once the policy is fixed, the MDP **degenerates into a Markov process (MP)**. For a discrete-time process with finitely or countably many states, this is a **Markov chain**. In the figure, the stochastic policy at $s_1$ becomes two transitions with probability 0.5 each.

### Agent–environment loop
The **agent** senses its state, maintains a policy, and executes actions. **Everything else is the environment**. After an action, the state changes and a reward comes back, which closes the loop.

## Q&A (key insights)

> [!question] Can all rewards be negative (or all positive)?
> Yes. What matters is the **relative** value of the rewards, not their absolute value. Adding the same constant to every reward (e.g., $-2$: $r_{\text{boundary}}=-3,\ r_{\text{target}}=-1,\ r_{\text{other}}=-2$) leaves the **optimal policy unchanged**. Optimal policies are invariant to affine transformations of the rewards (proved in Sec. 3.5).

> [!question] Should the reward depend on the next state $s'$?
> In general $r$ depends on $(s,a,s')$. But $s'$ itself depends on $(s,a)$, so we can marginalize it out:
> $$p(r\mid s,a)=\sum_{s'}p(r\mid s,a,s')\,p(s'\mid s,a)$$
> Writing the reward as $p(r\mid s,a)$ keeps the Bellman equation simple.
